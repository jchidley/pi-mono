# Domain documentation

Use a single shared context for this repository:

- Root `GLOSSARY.md` for domain terminology.
- Root `docs/adr/` for architecture decision records.

Before domain or architecture work, read the glossary and relevant ADRs
when present. Use their terminology and surface conflicts with recorded
decisions explicitly.

If these documents do not exist, proceed without creating placeholders.
Create them through domain-modeling work when terms or decisions are resolved.
