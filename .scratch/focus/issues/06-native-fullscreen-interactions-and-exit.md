# 06: Complete native fullscreen interaction and exit behavior

**What to build:** Focus behaves predictably with native search, selection, scrolling, terminal-mode changes, and exit output, without maintaining separate interaction machinery.

**Blocked by:** 02 — Add the live fullscreen focus toggle.

**Status:** ready-for-agent

- [x] Native search operates on the currently selected document. Hidden ordinary content is searchable by toggling out, not through new cross-view indexing or hidden-match reveal behavior.
- [x] Selection-copy copies visible content. `/copy` retains its existing last-assistant-text meaning, and `/transcript` remains unchanged.
- [x] Clear active selection and close search when toggling views so stale positions cannot apply to the replacement document. Handle the interaction through a narrow explicit boundary, not private-field probing or renderer replacement.
- [x] Prefer per-view scroll position and follow-end restoration only if straightforward, starting the first focused view at the bottom. If it requires substantial integration complexity, use native behavior or scrolling to the bottom instead.
- [x] Record which approved scroll behavior was selected and why. Test it while output grows and terminal dimensions change; do not introduce custom anchoring or promise exact restoration where native layout cannot support it simply.
- [x] Leaving fullscreen disables focus. Returning to fullscreen leaves ordinary view active, and invoking focus in regular mode explains the limitation. Preserve surrounding controls and ordinary renderer behavior.
- [x] Honor existing fullscreen exit settings. If configured to print a transcript, print ordinary output even when focus is active, including content hidden during focused viewing. If configured not to print, add no transcript output.
- [x] Do not create a separate focus export/exit subsystem, change ordinary thinking/tool preferences to achieve exit rendering, or destroy live ordinary components during view transitions.
- [x] Add focused integration tests for selected-document search, visible selection-copy, unchanged `/copy`, search/selection reset, terminal-mode transitions, chosen scrolling behavior, and both printing and non-printing exit settings.
- [x] Use existing viewport and renderer seams where possible and keep any necessary new interaction reset interface narrow. Validate externally observable behavior, not private search/selection structures.
- [x] Run affected tests and required code checks. Follow the native fullscreen interactive-testing workflow to toggle during work, search/select/copy, scroll, switch terminal modes, and inspect exit output using offline/faux inputs.
- [x] Report any compatibility limitation explicitly rather than silently substituting weaker behavior. Verify ordinary mode remains usable and keep upstream integration changes identifiable and bounded.

## Implementation and validation notes (2026-10-03)

- Added `TuiAltScreen.resetDocumentInteractions()`: closes native search and clears selection/drag state without closing unrelated overlays. Focus calls this boundary instead of probing private state or replacing the renderer.
- The configurable focus action is dispatched through the mounted renderer's input listener, including while native search owns keyboard focus. It remains unbound by default and ignores key-release events.
- Switching to regular mode disables focus through `TranscriptPresentation.disableFocus()`. The existing transcript-printing exit path already switches to regular rendering, so this also prints ordinary output without changing thinking/tool preferences. Non-printing exit remains unchanged. `/copy` implementation and `/transcript` workflow are untouched.
- **Scroll policy:** retain the approved scroll-to-bottom behavior on every view replacement. Native follow-end handles output growth and terminal relayout; per-view offsets would require layout-timing coordination with documents of different heights. No custom anchoring or exact-position restoration is promised.
